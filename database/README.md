# دليل تنصيب قاعدة البيانات - نظام الخطة التعليمية السنوية

هذا الدليل موجّه للفني المسؤول عن الاستضافة المحلية. القاعدة مبنية بـ **PostgreSQL** (مجاني ومفتوح المصدر، ومتوفر لـ Windows/Linux/macOS).

---

## 1. الملفات المرفقة

| الملف | الوظيفة |
|---|---|
| `schema.sql` | ينشئ كل الجداول والعلاقات والفهارس - يُشغّل **مرة واحدة فقط** عند التنصيب الأولي |
| `seed.sql` | يعبّي القوائم المرجعية الأولية (المواد، الصفوف، الاستراتيجيات، وسائل الايضاح، طرق التقييم، أمثلة مجالات) - يُشغّل بعد `schema.sql` مباشرة |

---

## 2. خطوات التنصيب

1. **تثبيت PostgreSQL** على الجهاز المحلي (نسخة 15 أو أحدث موصى فيها).
2. **إنشاء قاعدة بيانات فاضية:**
   ```
   createdb annual_plan_db
   ```
3. **تشغيل ملف المخطط:**
   ```
   psql -d annual_plan_db -f schema.sql
   ```
4. **تعبئة البيانات الأولية:**
   ```
   psql -d annual_plan_db -f seed.sql
   ```
5. **إنشاء مستخدم قاعدة بيانات مخصص للتطبيق** (بدل استخدام حساب الأدمن الافتراضي):
   ```sql
   CREATE USER app_user WITH PASSWORD 'كلمة_سر_قوية_هون';
   GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO app_user;
   ```
6. التطبيق (لما يُبنى) رح يحتاج **connection string** بهاد الشكل، ويُحفظ بملف إعدادات بيئة (`.env`) مو بالكود مباشرة:
   ```
   postgresql://app_user:كلمة_سر_قوية_هون@localhost:5432/annual_plan_db
   ```

---

## 3. النسخ الاحتياطي (Backup) - **الأهم**

بما إنه الاستضافة محلية، لازم جدولة نسخة احتياطية يومية تلقائية:

```
pg_dump -U app_user annual_plan_db > backup_$(date +%Y-%m-%d).sql
```

- على Linux: يُضاف هذا الأمر كـ **cron job** يومي (مثلاً الساعة 2 فجراً).
- على Windows: يُضاف كـ **Task Scheduler** بنفس الفكرة.
- **مهم جداً:** لازم تُنسخ ملفات الـ backup لمكان تاني غير جهاز السيرفر نفسه (قرص خارجي، أو مجلد على جهاز تاني بالشبكة) - نسخة احتياطية على نفس الجهاز ما بتحمي من عطل الجهاز نفسه.

---

## 4. التوسّع المستقبلي (Migrations)

أي تعديل على المخطط بالمستقبل (عمود جديد، جدول جديد) ما ينكتب مباشرة على قاعدة بيانات شغّالة فيها بيانات حقيقية. بدل هيك:

- يُنشأ ملف `migration_YYYYMMDD_وصف_التعديل.sql` منفصل يحتوي بس على `ALTER TABLE` أو `CREATE TABLE` الخاصة بالتعديل الجديد.
- يُشغّل بنفس طريقة `schema.sql` (`psql -d annual_plan_db -f migration_....sql`).
- بهيك بيضل عنا سجل كامل (تاريخ) لكل تعديل صار على القاعدة، وممكن نطبّقه على أي نسخة تانية من القاعدة (اختبار، تطوير) بنفس الترتيب.
