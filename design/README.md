# تصميم نظام "الخطة التعليمية السنوية" - تطبيق ويب لكل المدرسة

هذا التصميم مبني على بنية ملف الاكسل الحالي (شيتات المواد: رياضيات، اللغة العربية، العلوم، eng، עברית، المواضيع الاثرائية، بالإضافة لشيت "المجالات في كل موضوع" وشيت "جدول متابعة خطة عمل مركّز").

---

## 1. الأدوار (Roles)

| الدور | الصلاحيات |
|---|---|
| **معلم/ة (Teacher)** | يعبّي خطته السنوية لمادته وصفه فقط، يعدّل عليها بأي وقت |
| **منسّق مادة (Subject Coordinator)** *(اختياري)* | يشوف خطط كل معلمي مادته، يقدر يعلّق/يعتمد |
| **المركز المسؤول (Center Coordinator)** | يراجع قسم "التعلم الفردي" لكل معلم، يكتب ملاحظته (إن وجدت) وتاريخ الفحص - كتابة حصرية على هالقسم بس |
| **الإدارة (Admin/Principal)** | يشوف تقارير مجمّعة عبر كل المواد والمعلمين، يدير القوائم المرجعية (استراتيجيات، وسائل ايضاح...) |

## 2. مخطط قاعدة البيانات (ERD)

### الجداول الأساسية

**`users`** - المستخدمين
| العمود | النوع | ملاحظات |
|---|---|---|
| id | PK | |
| full_name | text | |
| email | text | unique |
| password_hash | text | |
| role | enum | teacher / coordinator / admin |

**`subjects`** - المواد
| id | name |
|---|---|
| 1 | رياضيات |
| 2 | اللغة العربية |
| 3 | العلوم |
| 4 | English |
| 5 | עברית |
| 6 | المواضيع الاثرائية |

**`grades`** - الصفوف (أول - سادس)

**`teacher_assignments`** - ربط معلم بمادة+صف+سنة دراسية
| id | teacher_id (FK) | subject_id (FK) | grade_id (FK) | school_year |

**`domains`** - المجالات التعليمية (مرتبطة بمادة+صف، مع النسبة من الامتحان - من شيت "المجالات في كل موضوع")
| id | subject_id (FK) | grade_id (FK) | name | exam_weight_percent |

**القوائم المرجعية القابلة للإدارة من الإدارة** (نفس القوائم المستخدمة كـ checkbox بكل المواد):

**`strategies`** (الاستراتيجيات) — id, name
**`visual_aids`** (وسائل الايضاح / الادوات) — id, name
**`assessment_methods`** (طرق التقييم) — id, name

> هاي الثلاث جداول عامة (Global) لكل المدرسة، الإدارة بس يلي بتقدر تضيف/تعدل/تحذف منها، وأي تعديل بينعكس فوراً على كل المعلمين.

### الخطة السنوية

**`annual_plans`** - رأس الخطة (خطة واحدة لكل معلم+مادة+صف+سنة)
| id | teacher_id (FK) | subject_id (FK) | grade_id (FK) | school_year | general_goal | specific_goal |

**`plan_entries`** - السطر الشهري بالخطة (يقابل الصفوف بكل بلوك شهري بالاكسل)
| id | annual_plan_id (FK) | month | unit_name | domain_id (FK) | sub_lessons (text) | success_indicator (text) |

**جداول الربط متعدد-لمتعدد (تطبّق سلوك الـ checkbox الحقيقي):**

- `plan_entry_strategies` — (plan_entry_id, strategy_id)
- `plan_entry_visual_aids` — (plan_entry_id, visual_aid_id)
- `plan_entry_assessment_methods` — (plan_entry_id, assessment_method_id)

**`individual_support_plans`** - قسم التعلم الفردي (سطر واحد لكل شهر لكل خطة سنوية)
| id | annual_plan_id (FK) | month | support_teacher_name | gaps_addressed (text) |

**`individual_support_students`** - أسماء الطلاب المسجلين بالتعلم الفردي (متعدد لكل قسم)
| id | individual_support_plan_id (FK) | student_name |

**`individual_support_assessments`** - الاختبار المحوسب والتقييم البديل (سطر لكل نوع، إذا حدث)
| id | individual_support_plan_id (FK) | assessment_type (enum: computerized_test / alternative_assessment) | occurred (bool) | assessment_date (date, null إذا ما حدث) |

**`individual_support_reviews`** - مراجعة المركز المسؤول (يملأها المركز فقط، لكل معلم/قسم)
| id | individual_support_plan_id (FK) | reviewed_by (FK → users, دور center) | review_note (text, اختياري) | review_date (date) |

> صلاحية الكتابة على `individual_support_reviews` محصورة بدور "المركز المسؤول" فقط - المعلم يقدر يشوفها لكن ما يقدر يعدّلها، بعكس باقي الجداول اللي المعلم مسؤول عنها بالكامل.

### خطط المركز (وحدة منفصلة - من شيت "جدول متابعة خطة عمل مركّز")

**`center_work_plans`**
| id | coordinator_id (FK → users) | title | team_goal | school_year |

**`center_work_plan_items`** - المبادرات (الدائرة الذهبية: What / Why / How)
| id | center_work_plan_id (FK) | task_what | process_how | target_audience | participants | success_criteria | assessment_tools | resources |


## 4. تصميم الواجهة (UI) - الشاشات الرئيسية

### أ) شاشة تسجيل الدخول
تسجيل دخول بالإيميل/كلمة السر، وتحويل تلقائي حسب الدور (معلم → لوحة المعلم، إدارة → لوحة الإدارة).

### ب) لوحة المعلم
- قائمة "خططي" (حسب المواد والصفوف المعيّن عليها)
- عند فتح خطة: نفس شكل الاكسل تقريباً لكن كجدول ويب تفاعلي:
  - كل شهر = بلوك قابل للطي (accordion)
  - عمود المجالات: قائمة منسدلة عادية (اختيار واحد)
  - أعمدة الاستراتيجيات / وسائل الايضاح / طرق التقييم: **checkbox حقيقية** (متعددة الاختيار) بدل الحل البديل بالاكسل
  - حفظ تلقائي (autosave) بعد كل تعديل

### ج) قسم التعلم الفردي (ضمن لوحة المعلم)
بطاقة منفصلة لكل شهر (بمعزل عن المجالات التعليمية العادية) تحتوي:
- اسم المعلم/ة المسؤولة عن التعلم الفردي
- أسماء الطلاب المسجلين (قائمة قابلة للإضافة/الحذف)
- الفجوات التي يتم العمل عليها
- الاختبار المحوسب: تفعيل (نعم/لا) + تاريخ يظهر فقط عند التفعيل
- التقييم البديل: نفس المنطق (تفعيل + تاريخ عند الحدوث)
- صندوق "مراجعة المركز المسؤول" بشكل بصري مختلف (خلفية مميزة) يوضح إنه غير قابل للتعديل من المعلم - يظهر فيه ملاحظة المركز وتاريخ الفحص بعد ما يعبّيها

### د) لوحة المركز المسؤول (دور منفصل)
قائمة بكل المعلمين اللي عندهم قسم "تعلم فردي" معبّى، مرتبة حسب الأحدث أو الأقدم مراجعة. عند فتح معلم معيّن: يشوف كل تفاصيل القسم (بدون تعديل)، وبالأسفل حقل لكتابة ملاحظته (اختياري) مع تاريخ الفحص - يُحفظ ويصير مرئي للمعلم كمراجعة رسمية.

### هـ) لوحة الإدارة - التقارير
- فلاتر: المادة / الصف / المعلم / الشهر / السنة الدراسية
- رسوم بيانية:
  - الاستراتيجيات الأكثر استخداماً (bar chart)
  - نسبة تغطية المجالات التعليمية مقابل النسبة بالامتحان (فجوات التغطية)
  - عدد الخطط المكتملة مقابل الناقصة لكل معلم (لمتابعة الانضباط بالتعبئة)
- تصدير أي تقرير لملف Excel أو PDF

### و) شاشة إدارة القوائم المرجعية (Admin فقط)
CRUD بسيط لإضافة/تعديل/حذف: استراتيجيات، وسائل ايضاح، طرق تقييم، مجالات تعليمية لكل مادة+صف.

### ز) وحدة خطط المركز
شاشة منفصلة لإدخال ومتابعة "الدائرة الذهبية" (Why/What/How) لكل خطة عمل مركّز.

## 5. ملاحظات تقنية عامة (بدون تنفيذ فعلي بعد)

- **قاعدة بيانات مقترحة:** PostgreSQL أو MySQL (كلاهما مجاني ومناسب للتثبيت المحلي، ويدعمان علاقات many-to-many بسهولة).

### الاستضافة المحلية - اعتبارات مهمة

بما إنه القرار استضافة محلية (داخل المدرسة)، في كم نقطة لازم تُحسم قبل التنفيذ:

| الموضوع | التفاصيل |
|---|---|
| **الجهاز (Server)** | جهاز مخصص (حتى لو كمبيوتر مكتبي عادي بمواصفات متوسطة كافي لعدد مستخدمين محدود) يشتغل عليه قاعدة البيانات + تطبيق الويب باستمرار |
| **الوصول** | افتراضياً بيكون الوصول بس من داخل شبكة المدرسة (LAN/WiFi الداخلي). لو بدكم وصول من البيت (المعلمين يعبّوا من منزلهم)، هاد بده إعداد إضافي (VPN أو IP ثابت + شهادة أمان SSL) وموصى فيه فقط لو في متابعة تقنية مستمرة |
| **النسخ الاحتياطي (Backup)** | **الأهم** - بما إنه ما في نسخ احتياطي تلقائي متل الحلول السحابية، لازم جدول آلي (يومي أو أسبوعي) يعمل نسخة من قاعدة البيانات ويحطها بمكان تاني منفصل (قرص خارجي أو حتى تخزين سحابي بس لغرض النسخ الاحتياطي فقط، مو للاستضافة) - عشان لو صار عطل بالجهاز أو انقطاع كهرباء مفاجئ ما تضيع بيانات سنة كاملة |
| **الصيانة** | لازم شخص بالمدرسة (أو بالمديرية/البلدية) يتابع إن الجهاز شغّال باستمرار، يعمل التحديثات، ويعيد تشغيل الخدمة لو صار انقطاع كهرباء أو تعليق |
| **الأمان** | حماية الجهاز بكلمة سر قوية + جدار حماية (firewall) أساسي، خصوصاً لو الجهاز متاح على الشبكة لعدة معلمين بنفس الوقت |

- **الصلاحيات:** تُطبّق على مستوى قاعدة البيانات (كل معلم يشوف بس صفوفه) وليس فقط بالواجهة، لحماية خصوصية بيانات كل معلم.
- **الهجرة من الاكسل:** يمكن كتابة سكربت لمرة وحدة يقرأ الملفات الحالية (openpyxl) ويعبّي الجداول أعلاه تلقائياً، بدل ما يعيدوا التعبئة يدوياً.

هذا تصميم أولي كامل (Schema + واجهات) جاهز نراجعه سوا قبل أي تنفيذ فعلي.
